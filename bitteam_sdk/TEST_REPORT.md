# Проверки SDK BitTeam 1.5.0

Дата: 2026-11-03. ОС Windows, Python 3.12.8. Отчёт относится к SDK, не к торговым стратегиям или развёрнутым ботам.

## Локальные проверки

Команда: `python -m pytest -c tests_sdk/pytest.ini tests_sdk --cov=bitteam_sdk --cov-report=term --cov-report=json:output-sdk/coverage.json --junitxml=output-sdk/tests.xml -q`.

Результат: **479 passed**, без skipped/xfail в Windows. Покрытие строк всего пакета около **80%**, а не 100%. В этот процент входят также интерактивные формы, примеры, optional-графики и PostgreSQL без подключённого сервера. Добавленные независимыми агентами проверки и исправления описаны в AGENT_REVIEW.md.

Проверены:

- Именованные методы всех 110 операций Swagger, параметры и построение путей. Четыре exchange/server callback/dev-операции намеренно отклоняются.
- HTTP Basic и сохранение старого конструктора с ключами.
- Прямой email/password вход, 2FA, затем подтверждение устройства, коды из двух каналов, неверные коды и неправильные ответы сервера.
- Cookies между auth/spot-поддоменами через настоящий локальный HTTPS с проверкой сертификата; изоляция аккаунтов и запрет передачи на неизвестный origin.
- Обновление spot-токенов, один refresh для одновременных истёкших запросов, refresh-токен в специальном заголовке, logout во время refresh, очистка сессии при отказе авторизации и сохранение при 5xx.
- Исходные JSON dict/list, стаканы, реальные bid/ask вместо последней сделки, сортировка последних сделок, фильтры и пагинация истории.
- Торговые маршруты для обоих режимов; передача amount/price строками; отклонение NaN/Infinity, отрицательных и обнулённых округлением сумм.
- Отсутствие повторов POST при auth-ошибке и timeout; отсутствие повторов GET с побочными эффектами; ограниченные повторы безопасного GET на 429.
- Разделение заявки вывода и подтверждения, валидация полей и сохранение ведущего нуля TOTP.
- nes v2: handshake, RPC, подписка/отписка, ping, сборка фрагментов, disconnect, timeout, server error и очистка ожидающих запросов.
- OHLCV с Decimal, сортировка, дедупликация и отсутствие пустых искусственных свечей.
- SQLite: обновление текущей свечи и получение последних N свечей по возрастанию времени.
- Распознавание частичного исполнения по сохранённому исходному объёму, без ложного вывода из статуса executed.
- Настоящий Windows DPAPI: шифрование/дешифрование и обнаружение повреждения. Пароли не допускаются закрытой схемой кэша.
- Восстановление cookies новым клиентом без login, сохранение обновлённых токенов, сохранение host-only/expiry, запрет другого API origin.
- Удаление локального кэша без HTTP, очистка при logout/невалидном refresh, сохранение кэша при временной ошибке, идемпотентный close без перезаписи новой сессии старым клиентом.

Форма Windows дополнительно проверена синтетическими значениями: вставка и счётчик, маскировка, переключение видимости значком глаза и наличие Ctrl+V/Shift+Insert bindings. Реальный буфер обмена при этой проверке не читался.

Ответы приватного локального сервера являются синтетическими контрактными примерами. Они не доказывают, что каждый приватный маршрут принимает такие же данные на production.

## Реальный публичный API

Команда: `python scripts_sdk/live_public.py`. Детали: LIVE_CHECKS.json.

**15 из 19 REST-проверок вернули успешные ответы:** asset, currencies, pairs, ccxt/pairs, rates, orders, trades, CMC assets/summary/ticker/orderbook/trades, orderbooks, pair, precisions.

Четыре расхождения:

| Маршрут | Ответ | Вывод |
|---|---|---|
| `/stats` | HTTP 500 / code 500000 | Публичный запрос без параметров из Swagger не работает. Не объявляется проверенным рабочим методом. |
| `/markdown/menu` | HTTP 500 / code 500000 | Серверная ошибка на публичном запросе из схемы. |
| `/altyn/banks` | HTTP 401 / code 401010 | Требует авторизацию вопреки PUBLIC в Swagger; SDK учитывает это. |
| `/altyn/client/` | HTTP 401 / code 401010 | Аналогичное расхождение по доступу. |

Эти неуспешные живые ответы включены в отчёт, не скрыты среди локальных passed.

**6 проверок истории/свечей успешны:** конфигурация, server time, описание пары, исторические свечи, свечи из публичных сделок, подтверждение подписки с последующей отпиской. История работает через `wss://history.bit.team/api/` и nes v2. Проверка ACK подписки не равна проверке фактического следующего рыночного события.

## Сборка и установка

Пакет собирается как wheel и sdist через PEP 517. Содержимое архивов проверяется на отсутствие `.env`, рабочих БД, логов и секретов сервисов. Также выполняются установка wheel в отдельное окружение и прогон тех же тестов против установленной копии, чтобы исключить зависимость от исходников и глобального окружения. Итоговые журналы сохраняются в output-sdk.

Изолированная проверка импортирует SDK из `output-sdk/venv-smoke/Lib/site-packages/bitteam_sdk`; каталог содержит 110 операций. Основной набор выполнен на aiohttp 3.14.3; изолированная установка использует aiohttp 3.14.5. Архивы wheel/sdist содержат схему API и не содержат `.env`, `.db`, `.log`, `.pyc` или кэш сессии. Журнал последней проверки: output-sdk/installed-tests.log.

## Реальная проверка аккаунта

Успешно проверены вход email/password, включённая Google 2FA, подтверждение устройства кодом из почты, создание spot-сессии, баланс до и после refresh, изменение обоих токенов и logout с очисткой cookies. Первый запуск обнаружил неправильное использование stock/balance; исправление на address/wallets проверено повторным успешным запуском.

Затем сессия сохранена через DPAPI. Другой процесс восстановил её без ввода любых учётных данных, прочитал баланс, обновил токены, прочитал баланс снова и сохранил обновлённый кэш. В этом процессе были только read_balance и refresh, без login, 2FA и торговых операций. Кэш оставлен для следующего запуска по запросу пользователя.

Подробности без секретов: ACCOUNT_CHECK.md. Пароль, одноразовые коды, токены и суммы баланса в отчёты не включены.

## Что не проверено на реальных внешних системах

- Реальная доставка кодов через Telegram, долговременное истечение refresh, повторное использование старого refresh и серверные правила отзыва сессии. Почта и обновление текущей пары проверены.
- Размещение/исполнение/отмена реальных ордеров, вывод средств, финансовые операции P2P, изменение настроек, создание API-ключей, верификация и fiat-платежи. Для них нужен отдельный сценарий проверки. Балансы через пользовательскую сессию проверены.
- PostgreSQL против живой базы; сервер для этих проверок не предоставлен. SQL-реализация включена как optional backend. SQLite проверена реально на временной БД.
- Открытие интерактивного окна Plotly и визуальный вид графика. Эти optional-функции не входят в проверку API.
- Приватный торговый WebSocket: публичный handshake старого endpoint был отклонён; SDK не обещает его работоспособность.

Полного production end-to-end подтверждения всех приватных функций нет. Авторизация, баланс, refresh и сохранение сессии проверены на реальном аккаунте без торговли; остальные ограничения перечислены выше.


## Расширение 1.5.0

Полный набор: 479 passed, без skipped/xfail. Дополнительно проверены ограниченная история по диапазону, отсутствие скрытого усечения и конфликтующих свечей, WebSocket nes v2, private reauth и закрытие владельца, точность Decimal стакана, SQLite-наблюдения, отсутствие записи приватных событий, сетевые планы вывода и разделение spot/P2P id. P2P каталог содержит 63 фиксированные операции сайта с источниками, включая GET с побочными эффектами; универсальный URL helper не экспортируется.

EXTENDED_CHECKS.json содержит 25 успешных живых проверок: 16 публичных и 9 с сохранённой пользовательской сессией. Подтверждены 1440 минутных свечей за полные UTC-сутки, публичные потоки, запись L2, новости, каталоги и подготовка USDT payload для трёх сетей. На аккаунте подтверждены восстановление без ввода пароля, ACK приватных подписок, чтение баланса/ордеров/уведомлений/P2P-кошельков, refresh и reauth. Приватные значения в отчёт не включены.

Публичный archive backend и часть market/docs backend не ответили успешно; их контракты отделены от живых подтверждений. Биржевая историческая L2-книга до начала локальной записи не подтверждена. Реальные финансовые операции не выполнялись; Telegram-доставка и каждый приватный endpoint не объявляются проверенными.
