# Независимая проверка SDK 1.4.1 - 2026-11-03

Три агента отдельно проверили auth/cache, API/transport/WebSocket и упаковку/probe/UI. Агенты не обращались к реальному аккаунту, пользовательскому кэшу или .env. Они воспроизвели ошибки на синтетических данных и добавили регрессионные тесты в три отдельных файла. Основной агент внёс исправления, затем агенты повторно проверили свои направления.

## Исправления

| Область | Найденная ошибка | Исправление |
|---|---|---|
| Выход и очистка | Отложенный login/2FA/device/resume мог восстановить сессию после выхода; поздний validation GET мог вернуть cookies | Отмена и ожидание tracked auth/validation tasks, проверка lifecycle, отбрасывание устаревших результатов |
| Недействительный кэш | HTTP 200 с auth-кодом 401010 не очищал кэш | Общая классификация окончательных auth-ошибок по коду и статусу |
| Keep-session probe | Временный 503 приводил к logout и потере кэша | Неполная проверка сохраняет действующую сессию и закрывает транспорт |
| Проверка баланса | Строка или список в result считались успехом | Требуется объект result; пустой объект допустим |
| Отчёт probe | Ошибка close оставляла running и могла уйти наружу | Обезличенная фиксация ошибки, гарантированные incomplete и finished_at |
| WebSocket revoke | Повторная подписка возвращала отозванный объект | Удаление из реестра и новая sub/RPC при повторном вызове |
| Фильтр ордеров | SessionAuth get_orders отправлял pair вместо where[pairId] | Разрешение нормализованного symbol в pairId и правильный query-фильтр |
| Retry-After | Значение 60 секунд урезалось до 30; HTTP-date игнорировался | Полный интервал и HTTP-date; при превышении бюджета ожидания возврат ошибки без раннего повтора |
